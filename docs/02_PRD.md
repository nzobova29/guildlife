# 02. PRD — Product Requirements Document

**Версия:** 0.1 (draft) · **Вход:** Product Brief / 8 UI-концептов · **Статус:** до разработки.

## 1. Обязательная граница MVP

| ID | Capability | P0 — MUST | Критерий приёмки |
|---|---|---|---|
| FR-01 | Гостевой демосеанс | Да | Вход без регистрации; данные посетителей изолированы друг от друга |
| FR-02 | Город | Да | Видна карта, 4 здания, 1 участок; клик открывает реальную панель |
| FR-03 | Кампании | Да | Создать цель, дедлайн (необяз.), описание; увидеть прогресс |
| FR-04 | Квесты | Да | Создать/изменить/завершить задачу; повторное завершение не даёт награду |
| FR-05 | XP и монеты | Да | Начисляет сервер транзакционно и один раз; баланс соответствует журналу |
| FR-06 | Строительство | Да | Один участок и 1–2 разблокировки; стоимость списывается ровно один раз |
| FR-07 | AI-планировщик | Да | Генерирует валидируемый план по цели; сначала предпросмотр, затем явное принятие |
| FR-08 | AI-статусы | Да | Показывает реальные `queued/running/awaiting_approval/done/failed`; ошибки доступны |
| FR-09 | Состояние после перезагрузки | Да | Задачи, баланс и здания сохраняются в PostgreSQL |
| FR-10 | Главный экран | Да | Пользователь видит сегодня, кампанию, ресурсы и путь к зданию |
| FR-12 | Демонстрационный seed | Да | Новый посетитель может исследовать мир с понятным набором демоданных |

### P1 — SHOULD / только если P0 закрыт

Фокус-таймер (не выдаёт завершение автоматически), простая канбан-доска, **FR-11: недельные итоги** (фактические квесты/XP), улучшение ещё одного здания, настройка персонажа. Первое вертикальное демо **не блокируется** отсутствием P1.

### P2 — LATER / не обещаем релиз

Внешние MCP/LangGraph агенты, авторизация через OAuth, длинная история персонажа, сюжетные бои, монетизация, многопользовательские гильдии, инвентарь, мобильное приложение, полноценная свободная расстановка тайлов.

## 2. Реальные пользовательские сценарии (Gherkin-lite)

**US-01: Создать цель.** Как пользователь, я хочу задать цель и получить разбиение, чтобы начать работу.

- Given открыта форма, When введена непустая цель, Then можно вызвать планирование.
- When модель отвечает, Then отображается предпросмотр этапов с возможностью редактировать.
- When пользователь подтверждает, Then задачи сохраняются; иначе никаких изменений.
- Когда AI недоступен, доступно ручное создание кампании и задачи.

**US-02: Получить честную награду.** Как игрок, я хочу видеть награду за выполненное дело.

- При первом завершении: задача `done`, начислены XP/монеты, создана запись в ledger.
- Повторный POST/двойной клик не дают вторую награду.
- После обновления страницы начисление и баланс остаются прежними.

**US-03: Построить здание.** Как игрок, я хочу обменять монеты на развитие города.

- Перед строительством видны цена, эффект и доступность.
- При недостатке ресурсов кнопка недоступна и объясняет причину.
- После успешной операции ресурсы списаны и на карте появился объект.
- Повторная покупка уже построенного объекта запрещена.

**US-04: Разобраться в работе AI.** Как пользователь, я хочу понимать статус действия AI.

- Отображаются фактические этапы; «72%» запрещено без достоверной базы.
- Ошибка, таймаут, отказ модели и ограничение бюджета имеют понятный UI.
- Текст агента не может напрямую изменять XP, кошелёк или БД без валидации.

## 3. Нефункциональные требования

| Область | Требование / рабочий ориентир |
|---|---|
| Производительность | Интерфейс интерактивен на типичном ноутбуке без обязательного WebGL; целевой p75 LCP <3 сек — проверить после первого билда |
| Доступность | Контраст текста, видимый focus, управление ключевыми кнопками с клавиатуры; целиться в WCAG 2.2 AA для интерфейса |
| Стабильность | Базовые действия работают при недоступном AI; friendly error и retry |
| Надёжность данных | Транзакционное начисление и строительство; миграции БД |
| Privacy | Без реальных пользовательских данных в seed; секреты только server-side; ограниченный сбор телеметрии |
| Изоляция | Гостевые сессии не читают/не модифицируют данные друг друга |
| Тестируемость | API и правила экономики покрыты unit/integration-тестами; e2e основного пути |
| Управляемость затрат | Ограничение числа AI-запросов, бюджет и timeout; локальный mock для разработки |
| Исходники | README не сообщает, что проект готов, пока это не подтверждено |

## 4. Сущности и UX-состояния

Основные: `Guest`, `Campaign`, `Milestone`, `Quest`, `LedgerEntry`, `CityPlot`, `Building`, `AiJob`.

Для каждой асинхронной операции предусмотреть `empty/loading/success/failure`, особенно для AI и строительства. Нужны ясные причины блокировки (пустая цель, нехватка монет, недоступный API).

## 5. Условия выхода MVP

- Выполняется весь сценарий `задача → награда → здание → перезагрузка`.
- AI выдаёт осмысленный план на одном проверенном тестовом наборе и корректно обрабатывает ошибку/некорректный JSON.
- Отсутствуют критические дефекты, дубль начислений и чужие данные.
- Реально работает опубликованная ссылка; README не противоречит фактическому состоянию.
- Есть демовидео/GIF, архитектура, ограничения и честное описание роли автора.

## 6. Вопросы до начала реализации

- Имеет ли смысл сохранять данные гостя между браузерными сессиями? **Предложение:** signed session cookie + TTL.
- Что значит «прошла кампанию»: все задачи выполнены или пользователь вручную закрывает? **Предложение:** все обязательные задачи выполнены.
- Как назначается награда? **Предложение:** только фиксированная сложность из 3 уровней; не свободный текст модели.
- Насколько интерактивна карта? **Предложение:** фиксированные точки и здания; drag-and-drop города — позже.
