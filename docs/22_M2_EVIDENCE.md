Два агента остановлены лимитом среды после основных изменений; результат не потерян. Главный агент продолжил интеграцию, AI-агент завершил серверные проверки. Независимый итоговый review всего объединённого diff отдельно не выполнялся; пройдены перечисленные проверки и ручной обзор границ API.

## Меню и профиль

Причина: `.sidebar` имел sticky-height100dvh без `overflow-y`, контент превышал высоту. При1280×720 profile bottom734px, при 1440×600 панель scrollHeight764px/clientHeight600px; на мобильном `.sidebar-bottom` скрывался вместе с профилем.

Исправление: отдельная прокрутка `.personal-sidebar`, профиль выше навигации; виден и на мобильном. Имя и PNG/JPEG/WebP фото хранятся **только в localStorage** (до2 МБ/4096 px), с валидацией, обработкой ошибок хранилища и возможностью убрать фото. XP передаётся из серверного состояния, не хранится в профиле.

Агент проверил1280×720,1440×600,390×844,320×568 и эквивалент zoom 200% (720×300). В коротком окне End прокрутил меню независимо от страницы; футер достижим. Upload PNG/перезагрузка, повреждённый файл, удаление фото и Escape/focus проверены в браузере. Скриншоты: `output/playwright/sidebar-*.png`.

## Работающий цикл

Гостевой cookie HttpOnly/SameSite=Lax, в БД хранится hash непрозрачного токена; TTL7 дней. Запросы проверяют владельца. Кампании и квесты сохраняются в PostgreSQL. Завершение блокирует wallet/quest, начисляет один раз и добавляет уникальную ledger-проводку. Ledger запрещает UPDATE/DELETE на уровне БД. Строительство блокирует wallet и проверяет единственный участок/баланс, затем транзакционно списывает цену.

Проверено браузером: **40 монет → medium-квест →60 монет/50 XP →сад 60 →0 монет/50 XP →reload**. Сад и состояние остаются. Повторный complete не платит второй раз. Второй браузер получает другой guest, чистый город/40 монет; чужой quest возвращает404.

## AI

GigaChat выбран пользователем. Реализованы OAuth/access-token, проверенный TLS, ограничение размера ответа64 КБ / max_tokens 4096, общий timeout, JSON schema и детерминированная валидация, persisted jobs. До 12 квестов / 2–5 этапов, ограничения времени; модель не получает tools и не управляет кошельком.

Квоты:2 вызова / гость / сутки, глобальный лимит **количества вызовов**, резервируется атомарно. По умолчанию лимит 0 и ключей нет: провайдер выключен. Accept создаёт campaign/milestones/quests атомарно; конкурентные принятия не создают дубль. UI показывает запрос/ожидание, реальные статусы, editable draft и явное принятие. Ручной сценарий доступен всегда.

**Проверено:** HTTP doubles с корректным/некорректным JSON, timeout, отказом, OAuth, TLS config; PostgreSQL ownership, quota, stale-job recovery, concurrent accept. **Не проверено:** настоящий ответ модели, тарифы, качество/реалистичность планов на E-01…E-03. Никаких платных вызовов не было.

Внешние агенты не запускаются и пока не подключаются; их событийный протокол описан отдельно в [20](20_EXTERNAL_AGENTS.md).
