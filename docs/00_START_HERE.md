# 00. GuildLife — точка входа

**Дата фиксации:** 05.11.2026 · **Статус:** `M1 — локальный прототип, готов к просмотру` · **Владелец продукта и delivery:** автор проекта · **Название:** рабочее.

## Зачем мы это делаем

Создать небольшой, но убедительный публичный pet-project: **изометрический RPG-город + рабочие квесты + один настоящий AI-планировщик**. Показать не объём кода, а способность пройти путь от гипотезы до релиза, приоритизировать, проектировать систему, объяснять ограничения и отвечать за качество.

## Фиксированные решения

- Стек: **React + TypeScript + Vite / Python + FastAPI / PostgreSQL + SQLAlchemy**.
- Один связный игровой цикл: цель → AI-план с подтверждением → квест → награда → город.
- Визуальный ориентир: городской симулятор в изометрии, тёмная панель, тёплый свет окон, сдержанная фиолетовая подсветка; **не мультяшная сказка**.
- Минимальный продукт работает **в гостевом деморежиме**, без платежей, соцфункций и внешних агентских интеграций.
- Реальные результаты, тесты, метрики и деплой не имитируем.

## Как читать пакет

1. `01_PRODUCT_BRIEF` → почему продукт существует.
2. `02_PRD` + `04_USER_JOURNEYS` → что именно делаем.
3. `05_GAME_DESIGN` + `06_AI_DESIGN` → правила самого сложного.
4. `07_ARCHITECTURE` + `08_DECISIONS_ADR` → как и почему реализуем.
5. `09_ROADMAP` + `10_BACKLOG` + CSV → чем занимаемся и в каком порядке.
6. `11_QUALITY_PLAN`, `12_METRICS`, `13_RISKS` → как доказываем качество.
7. `14_LAUNCH_PORTFOLIO`, `15_VISUAL_SYSTEM`, `16_WORKFLOW` → как выпускаем и представляем.
8. `17_SPRINT_01` → **отсюда стартует работа после согласования документов**.

## Текущее состояние

Реализован frontend в `frontend/`: четыре интерактивных SVG-здания, участок, навигация, форма кампании с проверкой, локальные квесты. Данные исчезают при перезагрузке; сервер, AI и экономика пока не подключены. Запуск — в README, результаты проверки — в [19_M1_EVIDENCE](19_M1_EVIDENCE.md). ## Как не превратить всё в бюрократию

Каждый документ должен отвечать на реальный вопрос. Новая фича — запись в backlog и изменение PRD, изменение важной технологии — новый ADR. Не пишем фальшивые стендапы, диаграммы ради диаграмм или KPI без пользователей.
