# GuildLife — профиль и сохраняемый игровой цикл

**Основание:** пользователь проверила M1, сообщила о недоступном левом меню/профиле и поручила отдельным агентам следующий этап. Базовый коммит `0910ea1`, рабочая ветка пользователя `develop`. Работа без автоматического merge/push.

## Разделение работы

- Агент sidebar_profile: отдельные Sidebar/PlayerProfile, локальное имя и фото, прокрутка меню и мобильный профиль. Не редактирует App.
- Агент backend_core: FastAPI, SQLAlchemy, PostgreSQL, Alembic, cookies/TTL/изоляция, кампании/квесты, транзакции наград и строительства, Compose/backend CI.
- Агент ai_planner: серверный адаптер, валидируемые планы, квоты, реальные статусы и транзакционное принятие, тесты ошибок провайдера.
- Главный агент: API-клиент, подключение UI, строительство на карте, UI AI review, сборка и браузерная проверка, подготовка deployment и обновление документации.

## Проверяемый результат

- [x] Левое меню доступно на малой высоте, профиль с выбранным пользователем именем/фото виден и редактируется.
- [x] Кампания и квест сохраняются в PostgreSQL; гостевые данные изолированы.
- [x] Выполнение начисляет серверную награду ровно один раз; баланс согласован с ledger.
- [x] При 40 монетах medium-квест даёт20 монет, затем сад стоит60; постройка и баланс переживают reload.
- [x] AI: реальный адаптер, строгая схема, ручной fallback; сохранение только при принятии. При отсутствии ключа честная недоступность, без выдуманного ответа.
- [x] Frontend показывает loading/error/retry; в случае недоступного API не выдаёт локальный макет за сохранённый прогресс.
- [x] Реальные PostgreSQL интеграционные/конкурентные тесты, frontend tests/lint/build, браузерный основной путь.
- [x] Compose, env-примеры, инструкции подготовки публичного демо. Публикация не выполняется без выбора hosting и реальной конфигурации.

## Контракт

`/api/v1/guest-session`, `/game-state`, `/campaigns`, `/quests`, `/quests/{id}/complete`, `/buildings/build`. Frontend использует same-origin proxy `/api`; сервер владеет wallet, гостевой cookie, ledger, city state. Одна площадка `plot-1`, варианты garden60/workshop100. Старт40, награды small25XP/10coins medium50/20 large80/30.

AI: POST `/ai/plan-drafts` {goal,deadline,hours,context}, GET `/ai/jobs/{id}`, POST `/ai/jobs/{id}/accept` с проверяемым Plan. Синхронный запрос разрешён исходным AI design; UI не изображает проценты или неподтверждённые этапы.

## Ограничения

Фото/имя профиля хранятся локально в браузере; это не система аккаунтов. Для AI и публичного URL требуются внешние настройки. Исследования с людьми, SLA и продуктовые метрики не имитируются.
